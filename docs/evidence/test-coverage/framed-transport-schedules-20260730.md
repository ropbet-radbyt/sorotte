## Boundary and independent schedule model

`ScheduledReader` is a test-owned `AsyncBufRead` implementation whose chunk
ends are independent of the production line reader. It exposes:

- one fully coalesced transport input;
- one-byte delivery;
- fixed widths from 2 through 17 bytes; and
- 64 deterministic pseudo-random schedules from a local fixed recurrence.

Together those are 82 exact fragmentation/coalescing layouts for a coalesced
Hello and Ready pair. The reader derives the exact maximum frame count from
the input's LF delimiters plus any unterminated suffix, requires every expected
frame, and performs one final EOF probe. A non-consuming or constant-frame
reader therefore fails promptly rather than hanging. Each decoded line is
compared byte-for-byte with the fixture, then applied through
`ClientApplication`. The final oracle requires the exact username and room,
an active session, and committed readiness for the named user.

The cancellation test uses a real bounded Tokio duplex. For every byte offset
before the first frame's terminating CRLF, it waits until the production
reader reports that the prefix has been consumed, drops that pending read,
requires a matching cancellation observation, writes the suffix, and then
requires both frames and the complete session state. This retains the
`TC-CLI-003` cancellation regression across the entire first frame rather than
at two hand-selected split points.

The EOF matrix covers every proper truncation of the Ready payload under both
one-byte and generated layouts. The complete Hello must commit; the truncated
Ready must fail decoding and must not commit readiness. Unterminated, lone-CR,
and CRLF-terminated valid final frames are exercised under 16 schedules each,
followed by empty and repeated EOF.

Four payload-limit seams separately require exact-MAX acceptance and MAX+1
rejection for LF and CRLF, including a one-chunk CRLF and a CRLF split after
one payload byte. They distinguish additive accumulated length from
multiplication and both same-buffer framing-CR decisions.

## Scope limits

The schedule matrix is deterministic generated transport coverage, not a
coverage-guided libFuzzer target. Cancellation uses a real Tokio duplex, while
the full chunk matrix uses a deterministic in-memory reader. The existing
loopback family retains real TCP schedules. TLS, reconnect backoff, arbitrary
session-state mutation, and server behavior remain separate boundaries. A
separate source-bound mutation shard measures the production framing
decisions exercised by these and the existing CLI tests.
