## Exact production seam

`crates/sorotte-cli/src/protocol_io.rs` remains the only implementation of the
inbound line accumulator. The `fuzz-support` feature adds a hidden, gated
re-export of the exact production `InboundProtocolLineReader` and
`MAX_INBOUND_PROTOCOL_LINE_BYTES`; it does not copy or conditionally replace
the framing algorithm. The underlying items are public only so the private
module can re-export them, and normal builds cannot name them through the
private module.

The standalone target then:

- uses the production accumulator for coalesced and scheduled reads;
- supplies deterministic coalesced, bytewise, fixed-width, and pseudo-random
  in-memory chunk schedules;
- cancels one first-frame read after a generated consumed-byte offset and
  resumes with the same production accumulator;
- derives an exact maximum frame count from the input and requires one final
  EOF probe;
- applies every returned frame, including a valid unterminated EOF frame,
  through public `ClientApplication::apply_protocol_line`; and
- compares complete session projections after each application step.

The maximum ordinary input has 65,536 bytes. Inputs deriving more than 64
frames return without session application, while the four special size-seam
seeds generate one exact bounded frame each.

## Independent oracles

The framing oracle is a separate byte walk. It splits only on LF, removes one
immediately preceding CR, checks the payload limit after that CR decision,
performs an independent UTF-8 conversion, and retains a final unterminated
frame at EOF. It does not invoke a Sorotte framing helper.

For both the coalesced and generated schedule, the target requires:

- the exact ordered line vector;
- the same `TooLong` or `InvalidUtf8` failure classification at the same
  prefix;
- no early EOF and no frame beyond the input-derived bound; and
- identical application acceptance, complete deterministic `Debug` session
  projections, and pending-protocol-message counts.

After each applied line, public room/user projections must agree. An active
session must retain both its username and room. Syntactically invalid JSON
must return an error and leave the session projection byte-for-byte unchanged.
Syntactically valid but semantically unsupported JSON may be rejected by the
ordinary public application boundary; that accepted/error outcome must still
be schedule-independent.

## Checked-in seed corpus

Ordinary inputs reserve their first four bytes as deterministic controls.
Control byte 0 selects the chunk mode modulo four: coalesced, bytewise,
fixed-width, or pseudo-random. Control byte 1 selects the fixed width or helps
seed the deterministic chunk generator. An odd control byte 2 enables one
first-frame cancellation. Control byte 3 completes the pseudo-random seed.
The target strips these four controls before framing.

| Seed | Control and purpose |
|---|---|
| `bytewise-state-chat.txt` | `1000`: bytewise State followed by Chat |
| `cancel-bytewise-hello.txt` | `1010`: bytewise Hello with first-frame cancellation |
| `cancel-pseudorandom-multi.txt` | `3010`: pseudo-random Hello/Set/Chat schedule with cancellation |
| `coalesced-hello-set.txt` | `0000`: coalesced Hello and playlist Set |
| `empty-and-null-frames.txt` | `3000`: empty, JSON `null`, and trailing empty frames |

## Limitations

This target proves bounded in-memory framing and session-application
invariants under generated bytes, chunk layouts, one first-frame
cancellation, EOF forms, UTF-8 failures, payload-limit seams, and deterministic
session projections. It does not claim:

- native GUI or UI Automation behavior;
- a real mpv process or mpv IPC transport;
- operating-system socket timing, packet loss, TLS, or server behavior;
- filesystem, SQLite, power-loss, or physical-storage durability;
- cross-process races or another thread scheduler;
- another sanitizer, architecture, operating system, or compiler;
- equivalence with every Python Syncplay behavior; or
- exhaustive JSON/session state exploration.

Future campaigns can extend those boundaries without weakening this exact,
source-bound local lane.
