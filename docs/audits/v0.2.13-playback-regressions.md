# Playback regressions in 0.2.13

The four reported symptoms were traced across the room protocol, client
coordinator and attached GUI player. The original intermittent sessions were
not recorded; these are controlled reproductions of concrete failure paths,
not a claim that every original occurrence had the same cause.

| Symptom | Failure path and correction | Regression coverage |
| --- | --- | --- |
| Positive room seek moves only the initiating player | A deliberate seek can overtake the acknowledgement of an earlier forced State. The server discarded it even when its transport revision was current. Revisioned seeks now reach authority validation despite this acknowledgement fence: current revisions can apply, while stale/future revisions receive a correlated correction. Existing readiness and control-authority checks still apply. | Server test `current_revision_seek_reaches_every_member_while_previous_ack_is_queued` covers two members and both pause states, explicit stale/future corrections, plus rejected telemetry and unscoped/zero revisions. |
| Rejected seek leaves a local offset | A correction can still name the initiating user as the last room controller. That attribution was mistaken for a successful self-echo. A scoped, counter-correlated correction now reconciles the physical position and expires on replacement, connection or media changes. Its identity survives an earlier room update without granting authority to rebase a later Play/Pause. | Client test `rejected_seek_is_corrected_even_when_canonical_state_names_the_local_user` covers unchanged/newer canonical revisions, warm/cold targets and both reply orderings. Existing delayed seek/Play/Pause acknowledgement regressions retain their strict wire-identity checks. |
| Remote pause changes participant readiness | A physical pause arriving after the command classifier's terminal grace became a native Not Ready gesture. One retained remote pause expectation now owns its delayed observation while canonical room pause agrees. Failed/replaced commands and later native gestures cannot reuse it. | Client test `delayed_remote_pause_observation_preserves_participant_readiness` also confirms a subsequent deliberate native pause still requests Not Ready. |
| Matching local file is labeled Plex | The direct-open match path chose the source from the requested playlist identity. The current-player path could also reuse a stale Plex attempt. Both now resolve the label from the loaded source; pending Plex identity matches require the current physical/logical file. | GUI test `opening_a_plex_playlist_identity_preserves_its_matching_local_source` covers both match paths, a stale attempt and an actual Plex identity. |
| Participant status stays on different scope or Loading | Scope can arrive after its unchanged transport is already applied, with no new RevisionApplied event. Fresh confirming observations now bind advisory scope without replaying control or barrier effects. Replayed cached positions also incorrectly reset recovery stability; only fresh position samples now affect that interval. | Client test `participant_status_adopts_scope_received_after_playback_is_already_applied` rejects cached and ahead-of-transport scope claims. Coordinator test `recovery_replayed_observations_do_not_restart_playback_stability` exercises interleaved live samples and replay. The readiness semantic flow checks startup status replacement. |

Readiness intent, technical eligibility, room transport authority and participant
status remain separate. In particular, late advisory scope adoption neither
reissues player commands nor emits another barrier acknowledgement.

Version preparation updates the workspace/path package versions in both lock
files without changing dependency versions. The generated architecture index
records the candidate; historical boundary evidence does not qualify it.
Exact-source hosted and isolated native campaigns are required before merge,
followed by publication of their retained artifacts under the release contract.

Qualification also reproduced an infrastructure failure before registration:
the Sandbox denied WMI queries to both its administrator and SYSTEM account.
Both guest entry points now read the same machine identity from firmware
registry values. The guard regression accepts the expected VM with WMI denied
and rejects foreign, missing and unreadable firmware. The Sandbox account,
bootstrap hashes, desktop and one-job authority checks remain required.

Hosted changed-line coverage also stopped at an uninstrumented enum or-pattern
containing a rest-only struct variant. The lexical classifier now recognizes
that pattern while keeping guards, field initializers and struct updates in
executable scope. Its regression reproduced the failure before the change.
The coverage report prompted an additional GUI regression for pending Plex
identity against missing, unrelated, physical-stream and logical source paths.

The mutation campaign then rejected a generated `||` connector between two
`let` expressions in `record_observation_outcomes`: Rust only accepts `&&`
there. The existing unviable-mutant policy now records that exact function,
operator and count with an expiry, based on the retained compiler failure.
All 37 viable mutants in that chunk were caught; survivor and timeout limits
remain zero. This policy adjustment requires fresh exact-source qualification.

The seek mutation chunks exposed nine missing negative-path assertions. Four
additional correction-authority regressions now cover malformed replies,
intent/scope/canonical-state changes between capture and admission, correction
expiry, and unchanged-base replay followed by the real rejection. Another
exact policy entry records the compiler's rejection of a fabricated default
correction candidate, which cannot supply the required causal identity.
