# v0.2.10 coordinated release attempt

The first [coordinated stable run](https://github.com/ropbet-radbyt/sorotte/actions/runs/34086010203)
used annotated tag `v0.2.10` at protected-main commit
`9f631f053ab431f56079e6ae4575fa5b0a9dc64a`. It finished unsuccessfully on its
original attempt on 7 September 2026. No stable release assets or server image
were published. The tag remains unchanged; the corrected candidate is v0.2.11.

guard now reports a bounded Git status inventory without file contents. A test
using a real Git checkout proves that a successful test command which changes
tracked inputs or creates an untracked cache file cannot obtain a workspace
receipt.

## Passing evidence and limits

The original stable lifecycle completed all 75 required transitions on Windows
and Linux, including actual missing-file recovery and replacement of the owned
player. The Windows workspace and all server behavior obligations passed. The
GUI archive was built from the qualified Windows binaries and passed its archive
and runtime checks. Its elevated updater check proved launch and refusal before
mutation, not installation or rollback.

The isolated Windows runner automatically unregistered and its owned guest,
processes and registration tokens were independently confirmed absent. All
original logs, official artifacts and local reproductions are retained under
`target/verification/release-v0.2.10/` in the release worktree. A normal cancellation
request arrived after the workflow had already failed and received HTTP 409;
no cancellation or retry changed the original attempt.

These passing boundaries do not make the failed run a complete release. They
also do not establish a speed improvement. The v0.2.11 candidate requires fresh
source-bound hosted and release qualification after the repairs are committed.
