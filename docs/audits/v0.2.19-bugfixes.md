# v0.2.19 bugfix regression inventory

This patch follows three bug-hunting passes against main at
`5f25d584eb9a7a18da67b08e4503d73cd40627ce` (v0.2.18). The inventory preserves the
finding identifiers from those passes. Each repair belongs to the existing
authority owner, with regression coverage at the boundary that reproduced it.

| Finding | Reproduced behavior | Repair and durable coverage |

The follow-on regressions include disappearing player items, retained-file
replay, later selection changes, final-row completion with an offset, an
accepted room switch whose acknowledgement is lost, stale membership restore
data, chat-command deletion followed by undo, media completion consumed by
another resolver, and exact Plex progress on a nonselected server. Readiness
controls reject predecessor playback, failure and buffering observations after
a source change or same-row replay, including repeated file publication, while
preserving ordinary no-playlist playback and active-target reordering. Offset tests
also cover a seek awaiting server acknowledgement, later positionless player
updates, and cancelling queued EOF only after a successful local seek.
Media prepared before connection binds to its first authoritative room on Hello;
that startup binding cannot adopt a different selected source or a later room.
For a confirmed Media Match alternate with a different basename, completion
uses the canonical row identity only when the active source resolution still
owns the exact physical load and media generation; unrelated alternates and
superseded selections remain unable to advance the playlist.
When several room requests are in flight, an earlier membership echo cannot
erase the latest requested destination before reconnect. Matching destination
acknowledgements and authoritative Hello assignments still retire that intent.
Both ordered player consumers retain the playlist selection owned by a physical
load before EOF. A duplicate-name selection or same-row replay cannot acquire
the predecessor's completion. A replay acquires completion ownership only from
its matching tracked seek receipt; a predecessor seek queued before the replay
cannot acquire the newer selection when it is consumed later. Harmless
unselected edits and active-row reorders retain valid completion.
Harmless modification-time drift is revalidated and
may republish the same audio signature; it is no longer treated as proof that
cached content is unchanged.

## Verification

The normal workspace suite includes the deterministic regressions. The two GUI
fingerprint tests require generated audio and ffmpeg/ffprobe; their explicit
ignored-test entries bind them to the existing generated-media CI obligation.
They are additional coverage, not replacements for the ordinary library tests.

Qualification also exposed a download fixture that assumed OS-thread sleeps
would deliver chunks before a short read timeout. The fixture now advances a
controlled clock only after receiving each chunk, with separate idle, overall
deadline and cancellation controls. Production download limits are unchanged.

The release version, both lockfiles and generated architecture catalog are
prepared together. Exact-source hosted checks, native execution and the full
nonpublishing stable candidate campaign must pass on the final PR head before
merge. Local assertions alone do not qualify a release. The release tag belongs
to the qualified candidate only after main promotion, as specified in
[the qualification contract](../PR_QUALIFICATION.md).
