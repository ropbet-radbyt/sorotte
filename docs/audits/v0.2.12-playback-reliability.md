# Playback reliability repairs for 0.2.12

The reported symptoms were large desynchronization during a local stall, native
player gestures escaping room synchronization, missed pauses, a jumping room
clock, unavailable participant status, right-shifted names and lowercase local
filenames. No incident recording was available. The regressions below reproduce
specific defects in the production paths; they do not claim to reproduce every
reported multiplayer incident.

| Defect | Repair and regression evidence |
|---|---|
| Acknowledged mpv delivery omitted transport observer registration. Native seek classification requires fields such as seeking and core-idle, which could remain unknown without a coordinator command. | Register the complete observer set when consuming acknowledged events. `acknowledged_player_pump_registers_transport_observers_without_a_user_command` exercises this path. |
| Acknowledged batches retained their original delivery reference, hiding queue residence from consumers after a stall. | Preserve observation timestamps and refresh delivery references, including redelivery. `acknowledged_player_batch_preserves_observation_age_after_a_consumer_stall` covers a 29-second queue delay. Lifecycle fanout tests still require immutable event identities, observations and outcomes, and idempotent replay. |
| Paused-player liveness used synchronous IPC reads. Unchanged subscribed fields were not resampled after consumers expired old telemetry. | Sample properties asynchronously with bounded cadence and one request in flight. Preserve the response's IPC ingress timestamp and event ordering; reject retired media/attachment responses. Tests cover unchanged paused/playing fields, a delayed read, retired and invalid responses, and preservation of provisional EOF without publishing a premature terminal phase. |
| An internal mpv IPC replacement did not reset the GUI's client-core attachment state. A previous Disconnected observation could keep fencing the replacement's telemetry. | Reset coordination and motion classification at a validated attachment replacement, then report its current availability. `ipc_attachment_replacement_reopens_reporting_and_retires_old_motion_state` checks the transition. |
| An authoritative pause waited for position alignment, and exhausted recovery retries could suppress further pause commands. | Dispatch pause before seek and retain pause's safety obligation outside the recovery budget, with cooldown and single-flight limits. Coordinator tests require physical pause observation before completion. |
| The displayed room clock updated only with runtime snapshots. | Interpolate the authoritative room position using a monotonic snapshot timestamp and request repaint every 100 ms. Pause/unavailable intent stays fixed; extrapolation stops after five seconds without a new snapshot. This display projection never supplies synchronization evidence. |
| A wide `add_sized` label centered short participant names. | Use an explicitly left-aligned allocation. The layout regression compares painted name/file edges for narrow and wide windows, with and without a controller icon. |
| Some media resolvers returned case-folded lookup keys directly to the player. | Recover Windows filesystem spelling before binding a resolution candidate and at direct-load entry, shared by mpv input, local metadata and the forced title. Regressions open mixed-case fixtures through folded paths and directory aliases, require the load to become Active and reportable, and retain candidate failure identity across path spellings. |

Room authority, participant evidence freshness and media/attachment fences remain
separate. Sampling an unchanged value is new evidence only after a successful,
scoped IPC response. A command acknowledgement alone never proves that the player
paused, sought or started.

This candidate bumps the workspace to 0.2.12. PR CI and the exact-commit isolated
Windows native run are required before merge. Publishing a release is a separate
operation.

## Release qualification follow-up

The first stable-tag Windows lifecycle run found another pause race before its
HTTP fault was injected. The baseline passed, but the HTTP scenario briefly
played and then returned the room to paused. Run `34284371641`, job
`102256473422`, retained the failed evidence; the Sandbox, runner registration
and registration tokens were removed. No release assets were published.

A focused client-core reproduction extended
`attached_local_play_suppresses_seek_preparation_pause_before_canonical_echo`
through the Play acknowledgement. It failed on the merged release source:
acknowledging Play removed the local intent while an older network seek
preparation still owned a pause. The next observation issued `SetPaused(true)`.

The follow-up retires that older preparation when the matching ordinary room
Play and the local player agree, before retiring the temporary intent. It
requires a real position sample after the seek, within the existing two-second
position-age budget and aligned with the frozen target. Seeking, cache pause,
idle transport and an outstanding authoritative seek-dispatch fence prevent
this handoff. Cached replay cannot manufacture the position proof, and server
barriers retain their authority. This handoff records supersession rather than
claiming new buffered-headroom evidence.

The regression covers both acknowledgement/observation orders, local and remote
room attribution, and a later legitimate room Pause. Coordinator cases reject
stale, future, replayed, missing or displaced position evidence and active
transport holds. Fresh hosted and native qualification of the follow-up is
required before publication.
