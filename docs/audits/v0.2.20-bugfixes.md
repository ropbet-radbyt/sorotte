# v0.2.20 bugfix regression inventory

This patch follows three reproducible bug hunts against main at
`0413c42e6f6ffb071c32dc851d1a6b44c80d4adc`, following the qualified v0.2.19
candidate `afee39f5cc091fc555030591cbe21f3dfdd272b9`. The original audit checkouts
and failing evidence remain separate from this repair branch. This inventory
maps every reported finding to production ownership and permanent regressions.

| Finding | Reproduced behavior | Repair and durable coverage |
| --- | --- | --- |
| MC-01 | Deleting or reordering an unrelated playlist row paused and reset the playing item. | Send negotiated lifecycle edits and their final selection in one existing Set envelope; compare the final media target atomically. Server `playlist_transport_regressions` checks observer transport, active deletion/replacement, replay, mixed peers and pure Syncplay controls. |
| MC-02 | Inserting a second file with the same basename could exchange exact local sources. | Preserve inserted row identity and occurrence order during reconciliation. GUI `insertion_and_source_choice` covers front/middle/end insertion and connected remove/undo; core `shuffle_undo_tests` preserves the selected duplicate occurrence. |
| MC-03 | Replay followed by append allowed the preceding playback's EOF to advance the playlist. | Retain a separate playback reset generation across harmless edits and bind completion to the physical reset receipt. mpv `replay_and_cache_provenance` and GUI `completion_regressions` reject predecessor EOF and accept completed successor playback. |
| MC-04 | An incoming playback State was assigned to the historical author's new room. | Scope State to the receiving membership. Server `playlist_transport_regressions` applies public fanout to a real observer and checks later seek behavior. |
| MC-05 | Choosing a source for an inactive row briefly opened that row and then reopened the active item. | Persist the row preference without dispatching an open unless it is active. GUI `insertion_and_source_choice` checks zero transient opens and exactly one later activation. |

Follow-on fixes retain duplicate selection through Undo, keep a buffering policy
alive until its own automatic pause is released, carry explicit synthetic
terminal evidence, and preserve pending-seek progress across repeated offset
changes. Queued Save & connect now uses the same submitted-baseline merge as
Save and storage relocation. Updater jobs already in flight retain their owned
paths; subsequent jobs use the new storage root.
Updater staging leases now explicitly release their lock when the last GUI
owner drops it. An unrelated Linux child inheriting the open file description
can no longer retain stale ownership. Independently acquired updater leases and
outstanding handoff reservations still protect the stage. Deterministic inherited
descriptor, independent-owner and reacquisition regressions cover this follow-on.

Deleting the active row now retains its explicit selection-reset intent even
when the successor has the same basename. The client sends the existing
standalone index request after the atomic edit and resets local playback;
inactive duplicate deletion and relocation still preserve transport. The reset
also starts successor readiness preparation, including when removal shifts the
active index, while rejecting predecessor playback evidence. Server observer
and GUI physical-file tests cover the nonzero-position failure, distinct-name
controls, and subsequent activation. Duplicate projection also distinguishes
insertion/removal from reordering so an asynchronous source selection keeps its
row identity.

Pure Syncplay sessions keep their existing separate edit/index frames. A new
compound edit also preserves playback for older peers in a mixed room. An older
initiating client sending separate frames cannot express that atomic edit;
its later standalone index remains a selection/replay and can still reset
transport in a lifecycle-governed mixed room. No timing heuristic suppresses
explicit replay. Cached Media Match validation uses the existing filesystem
identity contract; it does not claim to detect a replacement that deliberately
preserves all available identity metadata.

## Verification and release boundary

The normal Rust suites include these regressions. Semantic scenarios cover
duplicate ingestion, playlist source preference and settings persistence. Socket,
HTTP, filesystem and child-process fixtures own their resources and require no
live Plex account or physical desktop input. Older CLI socket fixtures now
complete the Hello exchange and drain replies before closing, so their EOF
assertions represent a completed session rather than an incomplete handshake.
The full default suite also exposed a startup-policy fixture reading a temporary
environment override owned by another test. It now uses that setting's existing
environment lock, with separate absent/present override controls; production
precedence and normal test concurrency are unchanged. Local file assertions use
canonical paths so Windows short-name temporary directories exercise the same
physical-file checks. The server binary fixture accepts intervening periodic
State frames while awaiting its List response within the original deadline.
Mutation inventory
validation explicitly includes the terminal fields emitted by the repaired
producer. Its test selector now includes the playback command-race regressions
that catch terminal-phase mutations; score thresholds are unchanged.
The Plex socket fixture also bounds its handshake reads so a broken protocol
writer fails promptly during mutation testing. Coverage classification follows
the existing test-directory convention and treats standalone multiline slice
pattern headers like the already-supported tuple headers; executable operands
and recorded zero-hit lines retain their coverage requirements.
The pending-seek offset regression also distinguishes a newly delivered sample
with the pre-seek capture timestamp from a strictly newer physical observation.
It rejects the stale sample as progress evidence and checks later recovery.
Mutation policy records the two compiler-proven invalid `||` replacements in
the new Rust let-chain by exact function and count; viable mutants still require
100% detection.
The Linux default-workspace run also exposed the inherited staging-lease lock.
A controlled fork with pipe barriers reproduced the final-owner failure on the
unchanged source and passed after the ownership correction; no timing retry or
weakened liveness assertion is used.
Three Windows Media Match fixtures also timed out before their lookup/abort
assertions. Those waits included fresh SQLite setup unrelated to the asserted
state transitions. The focused tests now control lookup replies and staged
payloads at the existing worker seams.
Separate tests retain real cold-index creation, reading, activation and abort
coverage; worker deadlines and production index behavior are unchanged. Local
phase timing did not reproduce the hosted timeout, and the original
failures remain retained rather than being treated as passed retries.

Version preparation updates the workspace, both lockfiles and architecture
catalog together. Exact-source hosted checks, isolated native execution and the
full nonpublishing stable candidate campaign must pass on the final PR head.
Local results do not qualify a release. The release tag belongs to that
qualified candidate after main promotion, as specified in
[the qualification contract](../PR_QUALIFICATION.md).
