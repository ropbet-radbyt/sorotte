# Syncplay Behind SWAG

This guide covers publishing `syncplay-server` through LinuxServer SWAG on Unraid or a similar Docker host.

The important protocol detail is that Syncplay is not HTTP and is not WebSocket. It is a raw TCP protocol on port `8999` with Syncplay STARTTLS negotiation. SWAG can still be the central public entrypoint, but nginx should proxy the TCP stream and the Syncplay server should perform TLS using the certificate files generated by SWAG.

Do not use a normal SWAG `proxy-confs/*.subdomain.conf` file for Syncplay. Do not use `listen 8999 ssl;` in nginx stream config for normal Syncplay clients, because nginx stream SSL expects TLS from the first byte while Syncplay starts with a protocol-level STARTTLS request.

## Generic Deployment Pattern

Target shape:

```text
Internet
  -> router TCP 8999
  -> SWAG container TCP 8999
  -> nginx stream proxy
  -> syncplay-server container TCP 8999
  -> Syncplay STARTTLS handled by syncplay-server
```

Requirements:

- A public DNS record for the Syncplay host, for example `syncplay.example.com`.
- A SWAG certificate that covers that hostname.
- SWAG publishing TCP port `8999`.
- Router/firewall forwarding public TCP `8999` to SWAG.
- SWAG and Syncplay on the same Docker network, or SWAG able to reach Syncplay by a stable LAN address.
- Syncplay able to read a certificate bundle containing `cert.pem`, `chain.pem`, and `privkey.pem`.

## SWAG Certificate

Add the Syncplay hostname to the certificate SWAG manages.

For SWAG `URL=example.com` and `VALIDATION=http`, add the subdomain label:

```text
SUBDOMAINS=...,syncplay
```

For DNS providers such as Cloudflare, the Syncplay DNS record must allow raw TCP traffic to reach your host. With Cloudflare this normally means DNS-only, not proxied, unless you are using a product that explicitly proxies arbitrary TCP ports.

Restart SWAG and confirm the certificate has renewed before enabling Syncplay TLS.

## SWAG Port Mapping

Expose TCP `8999` on the SWAG container:

```text
Host Port: 8999
Container Port: 8999
Protocol: TCP
```

Only SWAG should own the public host port. The Syncplay container should not also publish host port `8999` when SWAG is proxying it.

## Syncplay Container Network

Put Syncplay on the same Docker network as SWAG, then use the Syncplay container name as the nginx upstream.

Example:

```text
Syncplay container name: syncplay-rs-server
Docker network: same custom network as SWAG
Container port: 8999/tcp
Host port: not required
```

## Syncplay Certificate Bundle

Recommended hardened setup:

- Copy only the three certificate files Syncplay needs into Syncplay's own appdata directory.
- Mount that copied directory into Syncplay read-only.
- Run Syncplay as its default container user instead of the SWAG appdata user.

```text
Host path: /path/to/syncplay/appdata/tls
Container path: /tls
Access: read-only
```

Then set:

```text
SYNCPLAY_SERVER_TLS_CERT_PATH=/tls
```

The mounted directory must contain:

```text
cert.pem
chain.pem
privkey.pem
```

On the Docker host, copy the bundle from SWAG to the Syncplay TLS directory and make it readable by the default Syncplay container user, UID/GID `10001:10001`:

```sh
SYNCPLAY_CERT_DOMAIN=example.com \
  sh scripts/copy-swag-syncplay-certs.sh
```

The script defaults to these host paths:

```text
SWAG_ETC=/mnt/user/appdata/swag/etc
SYNCPLAY_TLS_DIR=/mnt/user/appdata/syncplay-rs-server/tls
SYNCPLAY_UID=10001
SYNCPLAY_GID=10001
```

If your paths differ, override those environment variables when running the script.

For renewal automation, run the same copy command from a host scheduler after SWAG has renewed certificates. A daily schedule is usually sufficient because Let's Encrypt renewals happen well before expiry. The server refreshes the TLS bundle on later STARTTLS attempts when the copied files change.

Directly mounting SWAG's live certificate tree into Syncplay also works, but it broadens what Syncplay can read. Use it only as a fallback:

```text
Host path: /path/to/swag/appdata/etc
Container path: /swag-ssl
Access: read-only
SYNCPLAY_SERVER_TLS_CERT_PATH=/swag-ssl/letsencrypt/live/<domain>
```

If direct mounting requires `--user=99:100` on Unraid, prefer the copied bundle setup instead. Running Syncplay as the SWAG appdata user lets a compromised Syncplay process read more SWAG-owned files in any mounted SWAG tree.

## Syncplay TLS Configuration

Use either the environment variable:

```text
SYNCPLAY_SERVER_TLS_CERT_PATH=/tls
```

or pass the server flag:

```text
--tls /tls
```

For the Docker image defaults, keep the server listening on all container IPv4 interfaces:

```text
--port 8999 --ipv4-only --interface-ipv4 0.0.0.0
```

## SWAG nginx Stream Config

Add a top-level nginx `stream` block. It must be outside `http { ... }`.

```nginx
stream {
    upstream syncplay_rs_server {
        server syncplay-rs-server:8999;
    }

    server {
        listen 8999;

        proxy_pass syncplay_rs_server;
        proxy_connect_timeout 10s;
        proxy_timeout 24h;
        proxy_socket_keepalive on;
    }
}
```

If SWAG reaches Syncplay through a LAN address instead of Docker DNS, use:

```nginx
server 192.168.1.10:8999;
```

Reload or restart SWAG after changing nginx config.

## Container Checks

From inside the Syncplay container:

```sh
printenv SYNCPLAY_SERVER_TLS_CERT_PATH
ls -l "$SYNCPLAY_SERVER_TLS_CERT_PATH"
test -r "$SYNCPLAY_SERVER_TLS_CERT_PATH/cert.pem" && echo cert-ok
test -r "$SYNCPLAY_SERVER_TLS_CERT_PATH/chain.pem" && echo chain-ok
test -r "$SYNCPLAY_SERVER_TLS_CERT_PATH/privkey.pem" && echo key-ok
```

Expected:

```text
cert-ok
chain-ok
key-ok
```

## External Verification

A basic port check should pass:

```powershell
Test-NetConnection syncplay.example.com -Port 8999
```

A Syncplay STARTTLS probe should return `true`:

```text
{"TLS":{"startTLS":"send"}}
```

Expected response:

```text
{"TLS":{"startTLS":"true"}}
```

After the STARTTLS response, a TLS client should validate the certificate for the Syncplay hostname and a Syncplay `Hello` sent through the encrypted stream should receive normal protocol messages.

If the response is:

```text
{"TLS":{"startTLS":"false"}}
```

traffic is reaching the server, but Syncplay did not load a readable TLS certificate bundle. Check the env var, mount path, file names, permissions, and whether the container was recreated after config changes.

## niceperson.club Deployment

Verified public endpoint:

```text
syncplay.niceperson.club:8999
```

SWAG container:

```text
Repository: lscr.io/linuxserver/swag
Network: Custom public
URL: niceperson.club
VALIDATION: http
SUBDOMAINS: www,vaultwarden,urbit,ftp,jellyfin,s3,console.s3,media.s3,stream,synclounge,matrix,livekit,syncplay
Host port 80 -> container port 80
Host port 1443 -> container port 443
Host port 8999 -> container port 8999/tcp
Appdata: /mnt/user/appdata/swag -> /config
```

Syncplay container:

```text
Repository: ghcr.io/ropbet-radbyt/syncplay-rs-server:latest
Container name: syncplay-rs-server
Network: Custom public
/mnt/user/appdata/syncplay-rs-server/data -> /data
/mnt/user/appdata/syncplay-rs-server/tls -> /tls:ro
SYNCPLAY_SALT=my-home-syncplay-room-salt-2026
SYNCPLAY_SERVER_TLS_CERT_PATH=/tls
```

Prepare the copied certificate bundle on the Unraid host:

```sh
SYNCPLAY_CERT_DOMAIN=niceperson.club \
  sh scripts/copy-swag-syncplay-certs.sh

chown -R 10001:10001 /mnt/user/appdata/syncplay-rs-server/data
```

After that, remove any direct `/mnt/user/appdata/swag/etc -> /swag-ssl` mount from the Syncplay container and remove `--user=99:100` if it was previously added.

SWAG stream config:

```nginx
stream {
    upstream syncplay_rs_server {
        server syncplay-rs-server:8999;
    }

    server {
        listen 8999;

        proxy_pass syncplay_rs_server;
        proxy_connect_timeout 10s;
        proxy_timeout 24h;
        proxy_socket_keepalive on;
    }
}
```

Verified from outside:

```text
DNS: syncplay.niceperson.club -> 87.121.73.171
TCP 8999: reachable
STARTTLS: {"TLS":{"startTLS":"true"}}
TLS: authenticated and encrypted
Certificate validation: ssl_policy_errors=None
Issuer: Let's Encrypt
Encrypted Syncplay Hello: server responded with normal protocol state
```
